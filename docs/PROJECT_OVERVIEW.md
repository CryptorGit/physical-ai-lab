# Physical AI Lab プロジェクト概要

## 1. プロジェクトの目的

Physical AI Lab は、物理世界をモデル化し、シミュレーション上でロボットや制御方策を検証するための研究リポジトリです。物理条件を変更した実験を通じて、方策の頑健性や異なる環境への汎化性能を調査します。

主な検証対象は、重力・摩擦・地形などの環境条件です。シミュレーション結果や学習ログを保存し、条件ごとの差分を定量的に比較できる構成を目指します。

## 2. 現在の重点テーマ

- MuJoCo による環境パラメータ実験
- Isaac Lab による深層強化学習
- 重力・摩擦・地形条件に対する方策の汎化
- ロボットモデルや実験結果の再利用性・再現性の確保

## 3. 中心となる研究課題

1. どの物理条件で方策が破綻するか
2. どのドメインランダム化が汎化性能に寄与するか
3. 異なる重力・地形条件の間で、どの知識や制御方策を共通化できるか

## 4. ロードマップ

### Phase 1: MuJoCo

- 既存ロボットモデルを動かす
- 重力を変更する
- 摩擦を変更する
- 実験結果を定量比較する

### Phase 2: Isaac Lab

- 既存の強化学習タスクを学習する
- 学習ログとチェックポイントを保存する
- 地球・火星・月を想定した環境で評価する

### Phase 3: Robustness

- Domain Randomization を導入する
- 学習時に存在しない未知条件で評価する
- 報酬設計の違いを比較する

### Later

- Gazebo + ROS 2 への展開
- Chrono による変形地盤のシミュレーション
- Basilisk による無重力・軌道環境の検証

## 6. 主なディレクトリの使い分け

### `experiments/`

実験単位でコード、設定、ログ、チェックポイント、動画、結果を管理します。実験を追加する場合は、シミュレータ名の下に `exp_NNN_<short-name>/` のようなディレクトリを作成します。

### `shared/`

複数の実験から参照する設定、評価指標、ロボットモデル、共通スクリプトを置きます。特定の実験だけで使うコードは、原則として `experiments/` 内に配置します。

### `docs/`

実験コードから独立した背景説明、概念整理、設計判断、論文メモを保存します。再現性や今後の設計に影響する判断は `docs/decisions/` に記録します。

### `results/` と実験内の成果物

プロジェクト横断で参照する結果は `results/` に集約します。一方、特定の実験に密接なログ、動画、チェックポイント、CSVなどは、その実験ディレクトリ内で管理します。

## 7. 想定する実験の流れ

1. `experiments/` に実験ディレクトリを作成する
2. `config.yaml` などに物理条件・実行条件を定義する
3. シミュレータを起動して実験を実行する
4. ログ、動画、チェックポイント、CSVなどを保存する
5. `notebooks/` または実験内の解析スクリプトで結果を可視化・集計する
6. 重要な結果や設計判断を `docs/` と `results/` に反映する

## 8. 再現性に関する方針

- 実験条件はコードに埋め込まず、可能な限り設定ファイルとして保存する
- 実験ごとに実行方法と必要な環境を README に記録する
- 学習ログ、チェックポイント、評価結果を対応づけて保存する
- モデルや外部資産の出典・ライセンスを確認する
- 既存の共通資産は `shared/` に集約し、実験間で重複させない
