## Measured leg zero and conversion

The ten active leg zeros are raw STS3215 present-position counts with EEPROM
offset zero:

```text
ID 10 right_hip_yaw    115       ID 20 left_hip_yaw    3832
ID 11 right_hip_roll   259       ID 21 left_hip_roll    365
ID 12 right_hip_pitch 3137       ID 22 left_hip_pitch   340
ID 13 right_knee       627       ID 23 left_knee        342
ID 14 right_ankle     3252       ID 24 left_ankle      2711
```

The runtime computes `offset_rad = (zero_raw - 2048) * 2*pi/4096` and uses
the measured model-space direction for target conversion:

```text
physical_servo_rad = measured_offset_rad + direction * model_joint_rad
```

Directions are `+1` for every right leg joint and every left hip joint;
`left_knee` and `left_ankle` are `-1`.  The inverse read path applies the same
direction after wrapping to `[-pi, pi)`.  This is the only permitted
simulation-to-real sign/offset path.

## Joint and servo ordering

The 14-axis simulation/action order is:

```text
left_hip_yaw, left_hip_roll, left_hip_pitch, left_knee, left_ankle,
neck_pitch, head_pitch, head_yaw, head_roll,
right_hip_yaw, right_hip_roll, right_hip_pitch, right_knee, right_ankle
```

The runtime HWI order is identical by name and maps to servo IDs:

```text
20, 21, 22, 23, 24, 32, 33, 31, 30, 10, 11, 12, 13, 14
```

IDs 10–14 and 20–24 use the USB leg bus at 1,000,000 baud.  IDs 30–33 use
the UART head bus.  The calibrated runtime disables all four head joints;
the policy/deployment adapter must therefore keep head targets exactly zero
and must never silently include head torque in a test.

## Sensors and runtime assumptions

- IMU: BNO055 over Raspberry Pi I2C, `IMUPLUS_MODE`, with the runtime's
  explicit axis remap.  `duck_config.json` controls `imu_upside_down`; the
  final package must pin this value and fail closed if it is absent.
- Foot switches: active-low GPIO inputs, left `D22`, right `D27`, internal
  pull-up.  The final package must record whether these are present; no
  simulation contact signal may be mislabeled as a physical switch reading.
- Servo ports: legs `/dev/ttyACM0`, head `/dev/serial0` by default.  A dry run
  must not open or write either port.
- The runtime refuses absolute target paths that cross the STS3215 raw 0/4095
  boundary and disables the commanded group on detection.  This guard remains
  mandatory in deployment.

## Simulation assets audited

- Exp004 MJCF is the hardware-safe calibrated backlash model under
  `artifacts/generated_playground/playground/open_duck_mini_v2/xmls/`.
- Exp004 contract fixes the 14-axis names, safe limits, zero/offset contract,
  reset margin, target margin and target slew guard.
- The existing exp003 `calibrated_hybrid_policy_v22.onnx` is a single
  command-conditioned actor input/output asset and is retained as the current
  single-policy baseline candidate.  The exp004 H5 planar/reverse PPO files
  are diagnostic experts and are not a final single-policy package.
- Existing exp003 calibrated polynomial/reference and backward profile assets
  remain lineage inputs only; their hashes must be copied into any final
  manifest rather than inferred from filenames.

## Audit conclusion

The measured 2026-07-29 leg calibration, byte-pinned runtime config, and
calibrated runtime conversion are reusable and sufficiently specified for the
offline deployment package. The single-policy simulation evidence,
transition/20x30 perturbation evidence, fixed-camera MP4, and dry-run target
audit are complete and hash-pinned. The package is still not physically
deployed: human-controlled electrical and hardware verification remains open.
