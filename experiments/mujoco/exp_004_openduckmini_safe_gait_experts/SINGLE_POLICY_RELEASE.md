## Decision

The release candidate is the single `base_v22.onnx` command-conditioned actor
with the hash-pinned calibrated backward target overlays. There are no
direction-specific neural-network weights in the release package. All eight
evaluator role names resolve to the same ONNX file; the three backward JSON
files are measured trajectory calibration, not policies.

The package is at `artifacts/single_policy_deployment_v1/`. It is
`SIMULATION_QUALIFIED_HARDWARE_PENDING`, not a claim of completed physical
robot testing.

## PDCA experiments that were rejected

The H5 target-space reverse experiments were intentionally not promoted:

- v14 used a fixed 54-row calibrated target table, BC scale 5, 1e-5 learning
  rate and 250,000 diagnostic interactions. Training/device/checkpoint audits
  passed; it is not a qualification run.
- v14 strict 1×6 s evaluation (`h5_routed_v14_margin_table_bc5_1x6s.json`,
  SHA-256 `292989f74ede054b54f65bff95dde7335294d75066e985d07b9b2413736c9951`)
  failed: reverse fell before completion and the forward/lateral/yaw routes
  retained gait-quality, slip, or drift failures. The v14 params SHA is
  `51d5cf584ed9304c363b70f4fe8af7ec40da75933189a4078577c25ef4c651a2`.

This rules out the hypothesis that a separate H5 reverse actor plus fixed
target-table BC is the root fix. The selected correction is the already
validated calibrated-hybrid path: one actor, measured offsets/signs, and
hash-pinned reverse target calibration with residual scale zero.

The attempted fresh exp004 20×30 rerun is not used as evidence: the launch
call reached the 10-minute tool ceiling, the detached WSL CPU process is still
being monitored, and no output file exists at this update. The independent
hash-pinned formal release record above remains the evidence; this rerun is
recorded as `NOT COMPLETED`, not as PASS or FAIL.

## Safety and deployment status

The conversion audit binds:

```text
policy action -> model target -> 0.050 rad inward target margin
-> one 2.0 rad/s slew at 50 Hz (0.040 rad/tick)
-> measured sign -> measured zero offset -> servo ID/raw target
```

The package manifest also records the SHA-256 of the reviewed Raspberry Pi
runtime entry point, HWI mapping, calibrated overlay controller, and ONNX
inference wrapper. These external runtime files are provenance references, not
silently copied or replaced implementations.

The 2026-07-29 user-confirmed raw leg zeros and mirrored directions are the
source of truth. The package also byte-pins the authoritative runtime
`duck_config` with `start_paused=true` and `imu_upside_down=false`; the live
launcher rejects a missing or mismatched config, including any joint offset
drift. The older `motor_internal_offsets.json` is explicitly superseded and is
not used. Head joints are disabled and forced to zero.

Hardware verification remains open. Read-only SSH to `openduck` timed out at
`<private-host-ip>:22`, and the last host capture showed no matching serial motor
device. No serial port was opened and no torque/write command was sent from
this workstation. The exact staged human test and PASS/FAIL conditions are in
`artifacts/single_policy_deployment_v1/deployment/hardware_test_plan.md`.

## Remaining DONE gate

Simulation, one-weight packaging, calibration provenance, offline target
sanity, fixed-camera evidence, and reproducibility documentation are present.
The only unclosed gate is human-controlled hardware verification (supported
stand through low-speed transitions) after the Raspberry Pi and motor bus are
reachable. Until that is run and recorded, the package must remain hardware
pending and must not be described as physically deployed.
